# TPS Notebook Navigator 10.1.0 — Choose Add or Replace on list-property drops

Dropping selected notes onto a list property value now asks before changing existing values. For example, dragging ten
notes onto `kind: note` when three have kinds shows **“3 of 10 notes already have values set for kind.”**

- **Add** keeps existing entries and adds the destination once.
- **Replace** leaves only the destination value, stored as a list.
- **Cancel**, Escape, or dismissal writes nothing. The native host initially focuses Cancel.

The choice applies to every selected note. The count includes distinct notes with nonempty values, including notes
already containing the destination. An entirely empty batch does not need a prompt. GCM list/kind definitions and actual
array values establish list semantics; standalone stored arrays work without GCM. Scalar, key-root and boolean
assignments keep their existing behavior. No settings, commands, dependencies, data migration or persisted preference
are added.

Only selected indexed metadata is read before choosing. Missing metadata blocks list batches. Add recomputes from
current source and preserves intervening additions. Replace skips changed property values or file identities, first at
cached preflight and again inside the existing native atomic writer. Unrelated properties and bodies remain intact.
No-op values skip the write queue. Concurrent changes are reported without retries. No new listener, vault scan, cache,
poller or repair system is introduced.

## Validation

- Full suite: **3,439 passed in 292 files**, no skipped tests. Focused coverage includes exact three-of-ten counting,
  all choices/dismissal, GCM kind/list and standalone arrays, deduplicated selection, empty values, scalar behavior,
  unavailable metadata, no-ops, moves/replacements, intervening edits and late edits inside the atomic callback.
- Full ESLint passes with existing warnings; changed source/tests have zero warnings. Styles, formatting, source
  namespace, operational identities and generated-artifact checks pass. A separate final production-mode build passes
  after tests.
- Exact artifacts deployed only to **Obsidian Plugin Test Vault**, reloaded as **10.1.0**, with Sync disabled and normal
  consumers enabled. Native UI inspection confirms readable count/consequence text, all three buttons, safe initial
  focus and Escape cancellation. Buttons wrap in scoped CSS; no physical phone acceptance is claimed.
- Ten synthetic notes: Add retained `task` on three and added `note` to all ten; repeated Add made zero writer calls;
  Replace made three calls, leaving all ten with only `note`. Cancel preserved original bytes and Escape made zero
  calls. All bodies and unrelated fields were preserved. A changed kind was preserved and skipped before entering the
  writer; the late-change atomic guard is also covered by tests.
- Native drag automation remained in the operating system drag session and did not deliver a drop event. Installed
  checks therefore used a temporary, fixture-restricted command calling the **same `applyPropertyNodeToFiles` owner used
  by the unchanged native drag handler**, followed by real UI button actions and independent file readback. This
  verifies the installed decision/write path, not the complete physical drag gesture. The temporary
  command/instrumentation was removed and fixtures archived.
- Foreground installed samples: first prompt preparation **2.7 ms**, repeated **1.3–1.5 ms**; next-frame samples
  **2.1–3.9 ms**. Every prompt preflight used exactly **10 metadata reads, zero vault enumerations, zero body reads and
  zero writes**. Final Add/repeated Add/Replace/Escape writer counts were **10/0/3/0**. Normal consumers caused one
  cached body read during Add and Replace; no long tasks were observed during these final samples. Separate
  concurrent-edit sampling observed existing consumer work/long tasks, so this is not a blanket performance claim about
  other consumers or devices. Human decision time is excluded from prompt timings.
- Enabled-plugin states unchanged. GCM, Health, Controller, Finances, Linter and Calendar settings hashes unchanged.
  Navigator's ordinary release-note owner advanced only `lastShownVersion` from 10.0.0 to 10.1.0; reversing that marker
  in memory exactly reproduces the prior data.json hash. No private file was overwritten.

Minimum Obsidian remains **1.11.0**. Public BRAT release is the production handoff. Production and iPhone
installation/acceptance are not claimed; user acceptance precedes production-ready status.
