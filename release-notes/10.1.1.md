# TPS Notebook Navigator 10.1.1

Bulk note arrivals no longer make the Properties root count and file-type visibility rescan the vault for unrelated property-tree, tag or decoration publications. They follow the existing batched file lifecycle and relevant visibility revisions. Actual file membership, hidden tags/properties, authored folder-note titles and drawing-preview classification still refresh their consumers.

No settings, defaults, commands, stored schema, notes, timers, watchers, persistent caches or public APIs are added or changed. Minimum Obsidian remains 1.11.0. This is a compatible patch for the shared desktop/mobile runtime.

## Validation

- 3,445 tests across 292 files pass, including 20 retained-hook consumer regressions. A 1,000-note fixture receives 100 unrelated property/tag/decoration/tree publications without another inventory or metadata query; real arrival/delete/move and exclusion changes refresh both scopes. Folder-note title and drawing-preview changes remain live.
- Full ESLint, Stylelint, namespace, operational-identity and artifact checks pass. Separate final production build passes.
- The initial full-suite attempt in the fresh isolated checkout found two missing generated-main.js artifact checks. Building the artifacts and rerunning the entire suite resolved both; no tests were skipped.
- Shared guarded helper deployed and CLI reloaded only TPS Notebook Navigator in Obsidian Plugin Test Vault. Sync remained disabled and normal consumers stayed enabled: GCM, Health, Finances, Calendar, Controller, Linter, Messager and upstream Navigator.
- Native UI showed the new synthetic food records in Navigator search. Editing a fixture title immediately updated its displayed row. Health indexed all 300 food logs in each measured 600-file batch. During arrival measurements there were zero modify/process calls.
- All enabled-plugin settings hashes are unchanged except Navigator's existing lastShownVersion marker (10.1.0 to 10.1.1), verified by reconstructing the original hash. No production note, setting, importer, credential or runtime was changed.

## Installed measurements

These are foreground Mac test-vault samples of sequentially arriving synthetic food definitions and linked logs, not a phone or network-throughput measurement. CPU profiling was enabled in both versions; each capture included two seconds of settling. Both controlled runs stayed visible and focused, with no modal overlays, the same Navigator root/list layout and a native Base open. The original published 10.1.0 artifacts were reinstalled for the controlled baseline, then the final 10.1.1 artifacts were restored.

| Initial Markdown inventory | 13,812 | 14,412 |
| Arrival time | 25.20 s | 21.25 s |
| Whole-vault getFiles calls | 576 | 238 |
| Time in getFiles | 832 ms | 385 ms |

| Longest task | 224 ms | 212 ms |

| Food logs indexed | 300 | 300 |

The larger after inventory makes this a conservative but imperfect comparison. An earlier first-after sample also reduced the targeted scans, but the earlier baseline did not record modal state (the UI subsequently showed a quick switcher) and is excluded from the primary timing comparison. The repeated runs establish removal of redundant plugin work, not elimination of every stall. Obsidian's own per-file link-metadata traversal remains a substantial CPU cost; this release does not patch core Obsidian or change sync behavior. A final-artifact repeat after archiving fixtures (15,012 starting Markdown files) recorded 269 getFiles calls, 24.18 s arrival time, 25 long tasks totaling 5,528 ms, a 24.5 ms p95 frame gap and a 291.7 ms maximum gap. All 300 logs were indexed with zero modify/process calls during arrivals. Thus fewer redundant scans are confirmed, but overall/worst-case latency improvement is not established by these growing-inventory samples. Worst-case frame gaps remain 200–300 ms on this Mac. Physical iPhone acceptance and production sync performance are unverified.

A separate fixed-size replay used the same 15,612-note vault and 600 owned synthetic notes. The baseline changed food protein/consumed quantities; the candidate restored their exact prior bytes through the same atomic API. Both were visible/focused with the same open consumers. Whole-vault getFiles calls fell from 44 to 0, and getRoot calls from 89 to 1. The writes finished in 4.82 s versus 4.08 s. Both had one long task (218 versus 243 ms) and the same 9.2 ms p95 frame gap. This isolates the removed redundant inventory work; it does not establish elimination of the remaining tree-build/core pauses. Each run made exactly 600 requested process calls and zero additional modify calls; other consumers still read bodies (not claimed eliminated).
